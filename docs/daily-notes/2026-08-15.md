# Daily Note — 2026-08-15

First daily note for this repo — everything from scaffold to a solid v1.0
lands in this one entry (started 2026-08-14, wrapped up today), same as
the web repo's very first combined note before its backend/frontend split
was worth having.

## Done today

- **Initial scaffold**: Jetpack Compose + Clean Architecture + Hilt,
  verified building for real (`./gradlew :app:assembleDebug`, including a
  genuine `kspDebugKotlin` Hilt-codegen run) before anything else got
  built on top of it. Getting there took three real dead ends — this
  machine's bundled JDK 25 broke older Gradle/Kotlin version assumptions,
  fixed by checking live Maven Central/`services.gradle.org` metadata
  instead of guessing — full story in `CLAUDE.md`'s "Environment
  reality" section.
- **Login + TodoList screens**, wired end to end from the start: network
  layer, token storage (DataStore), real backend error messages, loading
  states — applying lessons the web frontend only learned via a live bug
  report (Diego's "server not reachable" / dark-on-dark contrast reports
  led to fixes there too, see below).
- **Real production connectivity**, twice fixed after Diego actually ran
  the app on his phone: `10.0.2.2` (emulator-only) doesn't work on a
  physical device — debug builds now default to the real production API
  instead, with a `-PapiBaseUrl=` override for local-backend testing.
- **Auth guard, Logout, full list-detail screen** (item CRUD:
  add/remove/toggle-done, priority/category tap-to-cycle, due date via
  `DatePickerDialog`). Building the detail screen meant exercising every
  field/endpoint for the first time, which surfaced three real bugs in
  the initial scaffold's *assumed* API contract (`isComplete` vs. the
  real `isDone`, wrong HTTP verbs on complete/reopen, wrong response
  shape on create) — found by checking the web repo's actual committed
  OpenAPI spec, not by guessing again. Full writeup in `CLAUDE.md`.
- **Dark mode fixed by turning it off.** Diego reported unreadable
  text/buttons with system dark mode on — root cause was an incomplete
  dark color scheme (only `primary`/`error` overridden, everything else
  at Material3's generic dark defaults, which don't pair with Cloud
  Dancer's light-only palette). Forced to light-only until there's a real
  dark palette to replace this with.
- **Real Cloudflare Turnstile CAPTCHA** — no Android SDK exists for it,
  so `TurnstileCaptchaView` loads a new page in the web repo
  (`mobile-captcha.html`) via WebView and gets the token back through a
  JS bridge. No backend change needed at all. Registration is fully
  functional now, not a placeholder.
- **Release signing configured and verified live** — this was the actual
  Play Store hard-blocker (no signing key existed at all before today).
  Generated a 30-year upload keystore, hit a real PKCS12 quirk along the
  way (store/key passwords forced identical, silently), then ran
  `./gradlew :app:bundleRelease` for the first time ever — first real
  exercise of R8 minification, which had been configured but never
  actually run. Signature independently verified with `jarsigner
  -verify`.
- **Rename UI, in-app Terms/Privacy, a legible app icon.** Rename (list +
  item) closed a real gap — the backend supported it, nothing in the UI
  triggered it. Terms/Privacy reuses the web app's actual pages via
  WebView rather than duplicating the text. The icon went from unreadable
  (thin linework on a light background, didn't survive scaling to real
  launcher sizes) to legible (solid color + bold glyph) — still not
  *designed*, just no longer broken.
- **Account deletion** — found while prepping the actual Play Store
  submission checklist, not asked for up front: Google Play policy
  requires apps that support account creation to also offer account
  deletion. Backend got a new `DELETE /api/v1/auth/account` (cascades to
  the user's lists/items automatically via an existing FK), verified live
  end to end including a direct database check, not just a unit test.
  Diego then verified it himself independently — confirmed the account
  was actually gone from the database.
- **Play Store listing content drafted** (`play-store-listing.md`) —
  title, descriptions, content rating expectations, data safety form
  answers, ready to paste in once Diego's Play Console identity
  verification clears.
